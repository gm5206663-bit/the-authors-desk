# Start here — for agents

**Purpose:** reach the correct owner, current source and permission boundary before
editing. This is navigation, not a new story bible or a grant of authority.

## First five minutes

1. Read the user's actual task. Name the deliverable and the target project.
   If a story target is missing, do not choose one under a general cleanup request.
2. Read the destination repository's `AGENTS.md` and relevant nested instructions.
   Preserve the local contract. Read amendments, not just the first screen.
3. Use [task routes](TASK-ROUTES.md) and [the registry](registry.json) to find
   required reading, current-state owners and check commands. The registry stores
   paths, not chapter/rank copies. Listed commands run from their repository root.
4. Apply [authority and state](AUTHORITY-AND-STATE.md). Separate a live checkpoint
   from a dated profile, proposal, draft, historical receipt or generated view.
5. Apply [permissions](PERMISSIONS.md). Confirm scope and check for another agent's
   work using [coordination](COORDINATION.md). Record the base revision and baseline
   check results before changing anything.
6. Implement the smallest complete authorized change; run the applicable checks;
   inspect their output and scope, not only a badge. Record unrun and failing checks.
7. Follow [handoff and delivery](HANDOFF-AND-DELIVERY.md). Commit, re-fetch, resolve
   concurrent changes, push without force and verify the published revision.

Browse the [repository and project index](REPOSITORIES.md) for direct source links.

**Fast stop:** unclear author approval, contradictory live authority, missing canon
source, another agent's overlapping edit, inaccessible required source, or a failed
required release check. Stop the dependent action, preserve evidence, continue only
independent safe work. Never substitute an invented answer.

**One home per subject:** this folder owns cross-account onboarding. Sara owns
identity and operating lineage. Each serial owns its story state. The desk owns
account decisions and dated management receipts. The registry is the path map,
not a second state ledger. Existing local rules still govern their projects.
