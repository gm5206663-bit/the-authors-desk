# Worked example — an authorized chapter pipeline

**Hypothetical, not an authorization or a completed chapter receipt.** Suppose the
author names a serial and explicitly authorizes its next chapter.

1. Read that project's AGENTS/local instructions, current-state owner, author
   locks, acceptance status and last accepted chapters. Check another agent's
   ownership before editing. A named serial is not a waiver of other locks.
2. Verify the canon spine through the project's permitted source process. Record
   coverage, character knowledge and earned power before drafting.
3. Draft in the project's canonical home, at its style/length/continuity standard.
4. Run its actual local gate and required source/craft reviews. Run a checker
   selftest when modifying the tool; do not confuse it with checking the draft.
5. Synchronize state and generated views only at the acceptance stage defined by
   the local contract. A technically passing candidate may still await approval.
6. Deliver the chapter artifact, source/coverage, executed checks, state deltas
   and next safe action. Publish only when authorized; preserve the draft otherwise.

**Failure avoided:** a green gate becoming author acceptance, or a shared universal
script being used instead of the serial's specific release contract.
