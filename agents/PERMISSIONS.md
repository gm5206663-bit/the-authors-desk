# Permission boundaries

The user's task is the scope. These categories explain existing boundaries; they
do not create permission to edit every repository merely because it is public.

| Action | Default under an authorized management task |
|---|---|
| Inspect public files, measure, run known non-destructive checks | Proceed; record scope and revision. Inspect unfamiliar tools before running them. |
| Repair navigation or an unambiguous stale generated view | Proceed within task scope; preserve sources, run checks and receipt the change. |
| Prepare a proposal, source comparison or decision brief | Proceed; label it proposed and leave the ruling open. |
| Draft a story chapter | Named project + applicable authorization + current local readiness required. General maintenance is not a book selection. |
| Change locks, acceptance, epoch or approved numbering | Explicit author ruling required unless the precise operation was already delegated. |
| Unfreeze/revive, change major canon divergence, identity reveal, romance or power law | Author decision; do not infer it from broad trust. |
| Publish a candidate as accepted story | Follow the project's acceptance/release contract. Technical PASS alone is insufficient. |
| Remove a supposed duplicate | Verify identity and authorization; preserve the surviving home and a recovery receipt. No silent deletion. |
| Force-push or rewrite the surviving text's history | Not permitted by the standing management delegation. |
| Change repository visibility, archive or hide managed material | Do not: standing direction is public and unarchived. Credentials are never public artifacts. |

## Concrete traps

- **Golden Lion:** root kit contract identifies another agent's ownership. Obtain
  explicit author coordination before editing that serial.
- **Adaptive Prodigy:** frozen reference; do not continue or revive it.
- **Fire Phoenix:** published sequence and V2 candidate/promotion are different.
- **Supergirl:** acceptance and prose repairs have separate author boundaries.
- **Pokemon:** lifecycle descriptions conflict. Do not let a passing stage-0
  selftest decide which story instruction wins. Reconcile source evidence first.
- **Write-forward readiness:** a list of ready projects is not a selected target.

If blocked: finish independent safe work, leave an exact next question with
sources and consequences, and never record a proposal as a ruling.
