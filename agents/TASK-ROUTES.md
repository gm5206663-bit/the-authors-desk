# Task routes

The machine-readable [registry](registry.json) is the single repository/project
path map. This page owns the workflow, not copied live numbers. A command's
`purpose` states its scope; run it from the named repository root.

| Task | Route and required action | Delivery |
|---|---|---|
| Account maintenance | Desk contract and open decisions → registry → kit measurement tools. Capture a baseline; distinguish current defects from recorded findings. | Dated desk receipt, exact changed revisions and check scope. |
| Chapter writing | Select the named serial's source repo, not the shelf → local/nested AGENTS → current state + author locks → last accepted chapters → verified canon/coverage → local pipeline. | Chapter artifact + required source/coverage and state sync + acceptance/release evidence. |
| Continuity review | Load each fact's domain owner, approval status and epoch. Compare at exact revisions; do not manufacture a shared state across stories. | Evidence-based issue list; approved repairs only. |
| Canon research | Local CANON_ACCESS/CANON_GROUND and source-tier rules first. Distinguish source text from wiki pointer or model memory. | Source receipts, uncertainty and unresolved access needs in the local canon home. |
| Publishing | Read accepted source and publishing README first. Shelf/StoryOS are projections, not authority to repair prose. Sync/build using the local command after inspecting side effects. | Checked published output + source revision and release boundary. |
| Doctrine/method/identity | Read the appropriate doctrine/guide/Sara contract. No state transfer between holders or projects. | Source edits + provenance + refreshed manifest where required. |
| Tool maintenance | Read code and scope; run baseline fixtures; reproduce a defect; repair the implementation; rerun failing and clean cases. | Code + regression test + checks and unchanged standards. |
| Cleanup | Inventory → identity/hash comparison → one-home and preservation plan → scoped edit/move → links/gates. | Dated receipt; no unique history lost. |

## Finding the exact current chapter

Use a registered project route if one exists. For other kit serials start at the
root cockpit, then the serial's README/local instructions. Follow the declared
manifest/panel/accepted receipt. The registry intentionally does not contain a
"next chapter" scalar. Do not calculate acceptance from the maximum filename.

## Run checks honestly

A selftest tests a checker on fixtures; it does not inspect today's book. A pinned
CI baseline can remain green with known findings. A reporting sweep can finish
successfully while reporting hard findings. A release gate may require author
acceptance as well as structural correctness. Record which one you ran.

For the full public account audit use the kit's `SWEEP-OPERATIONS.md` procedure;
it declares public-only scope and the difference between findings and execution
failure. The guidance checker never executes commands supplied in the registry.
